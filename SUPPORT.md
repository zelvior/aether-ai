# Support

This document explains where to ask questions, where to report problems, and what kind of help
this project can realistically offer.

AETHER is an early-stage experimental research project maintained on a best-effort basis. There is
no support contract, no service-level commitment, and no guarantee of a response time.

---

## Where to go

| I want to… | Where |
| --- | --- |
| Report a reproducible bug | [Issue: bug report](.github/ISSUE_TEMPLATE/bug_report.yml) |
| Propose a feature or change | [Issue: feature request](.github/ISSUE_TEMPLATE/feature_request.yml) |
| Propose a research direction or experiment | [Issue: research proposal](.github/ISSUE_TEMPLATE/research_proposal.yml) |
| Report a security vulnerability | **Privately** — see [`SECURITY.md`](SECURITY.md). Never in a public issue. |
| Understand project scope and plans | [`README.md`](README.md), [`docs/ROADMAP.md`](docs/ROADMAP.md) |
| Ask how to contribute | [`CONTRIBUTING.md`](CONTRIBUTING.md) |
| Report a code of conduct concern | Privately, to the contact in [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) |

There is currently no chat server, mailing list, or forum for this project. If one is created, it
will be listed here. Do not create unofficial channels that present themselves as official.

## Before asking

Given the project's stage, a large share of questions have the same answer: **it does not exist
yet.** Please check [`docs/ROADMAP.md`](docs/ROADMAP.md) before asking when a component will be
available.

Also:

- Search existing issues before opening a new one.
- Read the relevant document in [`docs/`](docs/) first; most design and policy questions are
  answered there.
- Keep one topic per issue.

## What support looks like here

Because this is a research project rather than a product:

- **We can** discuss the design, review proposals, explain decisions, help reproduce a documented
  experiment, and clarify documentation.
- **We cannot** provide installation support for software that does not exist yet, debug private
  environments, guarantee any level of model quality, or offer commercial support.
- **We make no performance, compatibility, or fitness-for-purpose claims.** Please do not plan
  production use around this project at its current stage.

## Reporting something helpfully

For a bug report, include:

- What you expected and what happened.
- The exact version or commit you are using.
- Your platform, architecture (32-bit or 64-bit), toolchain and version, and build flags.
- A minimal reproduction, or the exact steps and input needed.
- Relevant logs or error output, with personal data removed.

If you are reporting a **lack of 32-bit support**, please say whether you attempted a real 32-bit
build and, if so, the exact failure. That information is genuinely useful; a guess is not.

## Privacy

Issues, pull requests, and comments on this repository are public. Do not post personal data,
credentials, or other people's confidential material. Attach only the smallest input needed to
reproduce a problem.
